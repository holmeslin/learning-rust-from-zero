# 為什麼需要所有權

## 本集目標

知道 Rust 沒有垃圾回收（GC），也不用自己 `free`，而是靠「所有權」規則，在編譯時期決定記憶體什麼時候釋放。

## 正文

### 記憶體總要有人收

程式用到 `String` 這類會變長的東西，就得向系統要一塊記憶體，用完再還回去。不還，記憶體會愈用愈少；還兩次，或是還了又繼續用，程式就會出怪事。所以每個語言都得回答同一個問題：誰負責還？

- **Go**：執行時有垃圾回收器（garbage collector，GC）在背景追蹤哪些資料沒人用了，替你回收。你寫程式時完全不用想這件事。
- **C**：自己 `malloc`、自己 `free`。最直接，但忘記 `free` 或 `free` 兩次，都是常見的 bug。
- **Rust**：沒有 GC，也不用自己 `free`。編譯器在編譯時期，就替每一塊記憶體決定好該在哪一行釋放，並自動把釋放的動作加到程式裡。

### 沒寫 `free`，記憶體還是會還

```rust
fn main() {
    for round in 1..=3 {
        let s = String::from("哈囉");
        println!("第 {round} 輪：{s}");
    }
}
```

執行結果：

```text
第 1 輪：哈囉
第 2 輪：哈囉
第 3 輪：哈囉
```

每一輪都建立一個新的 `String`，等於向系統要了一塊記憶體。程式裡沒有 `free`、沒有 `close`，背景也沒有 GC，但每一輪結束時，那一輪的 `s` 就已經被釋放了。這是編譯器在迴圈的 `}` 那裡，替你放進去的。

### 它怎麼知道

靠一套規則，讓編譯器隨時都知道「這份資料現在歸誰管」。管它的那個變數離開了，它就可以釋放。這套規則就叫**所有權**（ownership）。這一章會逐條講：

- 第 2、3 集：資料放在哪裡，以及所有權的三條規則。
- 第 4 集：釋放發生在哪一行。
- 第 5～6 集：把資料指定給別的變數時，管理權會轉手（move）。
- 第 7～8 集：想留下兩份時怎麼辦（`clone`），以及為什麼整數不受影響（`Copy`）。
- 第 9～11 集：把資料傳進函式、從函式拿回來時，所有權怎麼跟著走。

代價是：規則由編譯器檢查，沒照規則寫就編譯不過。Rust 讓你在編譯時期花力氣，換來執行時沒有 GC 的負擔，也不會有忘記釋放、釋放兩次這類 bug。

### 跟 Go 比一比

Go 靠 GC，所以幾個變數指到同一份資料、把函式裡建立的東西交給呼叫端，都不用多想，GC 會等到沒人用了才回收。代價是執行時要有回收器在背景工作，而且回收的時間點由 GC 決定，你控制不了。

Rust 選的是另一邊：不付執行時的成本，改成編譯時期要求你照規則寫。從 Go 轉過來，要先習慣一件事：Go 裡理所當然的寫法，例如 `b := a` 之後 `a` 和 `b` 都還能用，在 Rust 不一定成立。第 5 集就會遇到。

## 重點整理

- Rust 沒有 GC，也不用手動 `free`。
- 編譯器依所有權規則，在編譯時期決定記憶體在哪一行釋放，並自動放進釋放的動作。
- 代價是要遵守規則；沒遵守就編譯不過，不會拖到執行時才出事。
- Go 靠 GC，變數可以隨意共用資料；Rust 靠規則，同一份資料要有明確的負責人。
