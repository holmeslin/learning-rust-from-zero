# `clone`

## 本集目標

用 `.clone()` 把 heap 上的資料複製一份，讓兩個變數各自擁有一份，並知道它有成本。

## 正文

### 明確複製一份

move 之後原本的變數不能用。如果兩個變數都要有一份，就用 `.clone()`：

```rust
fn main() {
    let s1 = String::from("哈囉");
    let mut s2 = s1.clone();
    s2.push_str("，世界");
    println!("{s1}");
    println!("{s2}");
}
```

執行結果：

```text
哈囉
哈囉，世界
```

`s1.clone()` 會在 heap 上另外要一塊空間，把「哈囉」複製進去，回傳一個新的 `String`。`s1` 還是原來的擁有者，`s2` 擁有的是複本。兩份資料各管各的，所以改了 `s2`，`s1` 完全不受影響。`clone` 跟 `push_str` 一樣是方法呼叫，先照抄，第 5 章會解釋。

```text
s1 ---> 哈囉        （heap 上的一份）
s2 ---> 哈囉，世界   （heap 上另外一份）
```

### `clone` 有成本

`clone` 要向系統要記憶體，還要把內容整份複製過去。文字有一百萬個字，就複製一百萬個字。相對的，上一集的 move 只複製三個小欄位，永遠很便宜。

Rust 要你親手寫出 `.clone()`，就是讓「這裡花了成本」看得見。它不會在背後偷偷複製。

### 不要拿 `clone` 當止痛藥

看到 `value moved here`，很容易想：加個 `.clone()` 就好了。編譯是會過，但先停一下，問問自己：兩個變數真的各需要一份嗎？很多時候只是想「看一眼」，不是要「擁有一份」。第 4 章的借用，就是為這種情況設計的，到時候會發現很多 `.clone()` 根本不需要。

真的需要兩份獨立的資料，例如一份留著備份，另一份要修改，這時用 `.clone()` 就是對的。

## 重點整理

- `s.clone()` 複製 heap 上的資料，回傳新的 `String`；原本的和複本各自擁有一份。
- `clone` 之後兩個變數都能用，改其中一個不影響另一個。
- `clone` 有成本（要記憶體、要複製內容），所以必須明寫；move 只複製三個欄位，很便宜。
- 不要為了讓編譯成功就加 `.clone()`；先想想是不是真的需要兩份。
