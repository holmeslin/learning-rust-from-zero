# move

## 本集目標

知道把 `String` 指定給另一個變數時，所有權會轉手，這叫 move，而且不會複製 heap 上的文字。

## 正文

### 指定給另一個變數

```rust
fn main() {
    let s1 = String::from("哈囉");
    let s2 = s1;
    println!("{s2}");
}
```

執行結果：

```text
哈囉
```

`let s2 = s1;` 沒有再做出一份「哈囉」。它把 `s1` 擁有的那個 `String` 交給 `s2`，從這一行起，擁有者是 `s2`。這個動作叫 **move**（移轉）：值沒有動，換的是擁有者。

### move 的時候發生了什麼

第 2 集說過，`String` 在 stack 上有三個欄位，指向 heap 上的文字。move 時，這三個欄位被複製給 `s2`，heap 上的文字完全沒動：

```text
let s1 = String::from("Hello");

s1: [ ptr | len 5 | cap 5 ] ---> H e l l o

let s2 = s1;

s1: （失效）
s2: [ ptr | len 5 | cap 5 ] ---> H e l l o
```

所以 move 很便宜，文字再長也一樣：只複製三個小欄位。

為什麼 `s1` 要失效？假設它還有效，`s1` 和 `s2` 就指著同一塊 heap 記憶體。兩個變數離開作用域時，各自要把它還一次，同一塊記憶體被釋放兩次（double free），這是 C 裡經典的 bug。規則 2 要求同一時間只有一個擁有者，move 之後 `s1` 就不算擁有者，作用域結束時只有 `s2` 會去還。

至於 `s1` 失效後還碰它會怎樣，下一集看。

### 哪裡會 move

這一集看到的是 `let` 指定。把值傳進函式、從函式回傳，也會 move，第 9、10 集會講。

### 跟 Go 比一比

Go 的 `b := a` 不會讓 `a` 失效。拿 slice 來說：

```go
a := []int{1, 2, 3}
b := a // 複製 slice 的表頭，a、b 指到同一個底層陣列
b[0] = 99
fmt.Println(a[0]) // 99
```

`a` 和 `b` 都能用，也共用同一份資料，誰改了，另一邊都看得到，要靠 GC 在最後沒人用時才回收。Rust 的 `let s2 = s1;` 則是明確換手：只剩 `s2` 能用，資料不會被兩邊同時握著。

## 重點整理

- 把 `String` 指定給另一個變數（`let s2 = s1;`）是 move：所有權轉給 `s2`。
- move 只複製 stack 上的三個欄位（指標、長度、容量），heap 上的文字不會複製。
- move 之後，原本的變數 `s1` 不再是擁有者，所以作用域結束時只有 `s2` 會釋放記憶體，不會 double free。
- 傳進函式、從函式回傳也會 move（第 9、10 集）。
- Go 的 `b := a` 之後 `a`、`b` 都能用且共用資料；Rust 的 `=` 對 `String` 是換手。
