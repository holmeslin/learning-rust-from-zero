# 未使用變數警告與 `_x`

## 本集目標

看懂「未使用變數」的編譯警告，並知道用 `_` 開頭的名字表示「故意不用」。

## 正文

### 警告不是錯誤

建立了變數卻從來沒用到，Rust 會發出**警告**（warning）。警告不會擋住編譯，程式照樣能跑：

```rust,warn
fn main() {
    let x = 5;
    let y = 10;
    println!("{y}");
}
```

編譯警告：

```text
warning: unused variable: `x`
 --> src/main.rs:2:9
  |
2 |     let x = 5;
  |         ^ help: if this is intentional, prefix it with an underscore: `_x`
  |
  = note: `#[warn(unused_variables)]` (part of `#[warn(unused)]`) on by default
```

執行結果：

```text
10
```

警告說 `x` 沒有被用到，箭頭旁的 `help` 還建議：如果是故意的，在名字前面加底線，寫成 `_x`。

### 處理的三種方法

看到這個警告，依情況選一種：

1. 變數是多餘的：刪掉它。
2. 你本來就打算用它：把漏掉的程式碼補上。
3. 故意不用：名字前面加 `_`。

第三種的寫法：

```rust
fn main() {
    let _x = 5;
    let y = 10;
    println!("{y}");
}
```

執行結果：

```text
10
```

名字以 `_` 開頭，就是告訴編譯器「我知道這個變數沒用到」，警告就不會出現。`_x` 還是一個普通的變數，只是少了警告。

最常見的用途是迴圈變數：只想重複 N 次，不需要知道現在是第幾圈。

```rust
fn main() {
    for _i in 0..3 {
        println!("哈囉");
    }
}
```

執行結果：

```text
哈囉
哈囉
哈囉
```

單獨一個 `_` 也有特別的意思，第 2 章會介紹。

另外，變數用 `let mut` 建立卻從來沒有改過值，編譯器也會警告「不需要 `mut`」，處理方式是拿掉 `mut`。

### 別把警告留著

警告表示程式雖然能跑，但很可能有地方寫錯，例如變數名稱打錯、忘了把算出來的值拿去用。養成習慣：看到警告就處理，讓 `cargo run` 不再出現任何警告。本書所有範例都沒有警告。

### 跟 Go 比一比

Go 對「宣告了卻沒使用的區域變數」是**編譯錯誤**：`declared and not used`。要消掉就得寫 `_ = x`。

```go
x := 5
_ = x // 假裝用過
```

Rust 只是警告，程式仍然能編譯執行，所以很容易一路忽略，累積一堆警告。第 12 章會介紹 `cargo clippy`，它會找出更多類似的問題。

## 重點整理

- 變數沒用到，編譯器會發出警告 `unused variable`；警告不擋編譯，但請把它處理掉。
- 處理方式：刪掉、補上用法，或把名字改成 `_` 開頭，例如 `_x`、`_i`。
- `_` 開頭的名字表示「故意不用」，不會有警告。
- `let mut` 卻沒有改值，也會有警告，拿掉 `mut` 即可。
- Go 對未使用變數是編譯錯誤，Rust 只是警告。
