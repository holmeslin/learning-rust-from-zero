# `Rc<T>`

## 本集目標

用 `Rc<T>` 讓同一份資料有好幾個擁有者，會用 `Rc::clone` 與 `Rc::strong_count`，並知道 `Rc` 裡的值不能改。

## 正文

### 一份資料，兩個擁有者

所有權的規則是一個值只有一個擁有者。但有時資料就是共用的：兩家分店用同一份菜單。照第 3 章的寫法，菜單只能 move 給其中一家，另一家再用就是 E0382；改成 `.clone()` 的話，兩家各有一份獨立的菜單，不是共用。

`Rc<T>`（reference counting，參照計數）就是解法：值放在 heap 上，旁邊多記一個「現在有幾個擁有者」的計數。每多一個擁有者，計數加 1；擁有者被 drop，計數減 1；減到 0，值才真的被 drop。

```rust
use std::rc::Rc;

struct Menu {
    name: String,
}

impl Drop for Menu {
    fn drop(&mut self) {
        println!("{} 作廢", self.name);
    }
}

struct Branch {
    menu: Rc<Menu>,
}

fn main() {
    let menu = Rc::new(Menu {
        name: String::from("夏季菜單"),
    });
    println!("擁有者：{}", Rc::strong_count(&menu));

    let taipei = Branch {
        menu: Rc::clone(&menu),
    };
    println!("擁有者：{}", Rc::strong_count(&menu));
    {
        let taichung = Branch {
            menu: Rc::clone(&menu),
        };
        println!("擁有者：{}", Rc::strong_count(&menu));
        println!("台中用 {}", taichung.menu.name);
    }
    println!("擁有者：{}", Rc::strong_count(&menu));
    println!("台北用 {}", taipei.menu.name);
}
```

執行結果：

```text
擁有者：1
擁有者：2
擁有者：3
台中用 夏季菜單
擁有者：2
台北用 夏季菜單
夏季菜單 作廢
```

- `Rc::new(...)` 建立第一個擁有者，`Rc::strong_count(&menu)` 讀出目前的擁有者數量。
- `Rc::clone(&menu)` 建立另一個擁有者：計數加 1，指向同一份 `Menu`。內層的 `}` 讓 `taichung` 離開作用域，計數減回 2。
- 全部擁有者都走了（`main` 結束）計數才是 0，這時 `Menu` 的 `drop` 才印出「夏季菜單 作廢」，而且只印一次。

```text
taipei.menu   --+
                +--> [ 計數 2 | Menu { name: 夏季菜單 } ]   (heap)
taichung.menu --+
```

`Rc::clone` 不會複製 `Menu`，只是計數加 1，很便宜，跟 `String::clone` 複製整段文字不同。`menu.clone()` 也行，意思一樣；慣例寫成 `Rc::clone(&menu)`，讀程式的人一眼就知道這不是深層複製。`Rc<Menu>` 可以直接 `.name` 讀欄位，因為它實作了 `Deref`（第 3 集）。

### `Rc` 裡的值不能改

兩個擁有者都能讀，要是其中一個還能改，另一個就在毫不知情時被改了值，跟第 4 章第 4 集的規則（多個 `&` 或一個 `&mut`）衝突。所以 `Rc<T>` 只給讀：

```rust,compile_fail=E0594
use std::rc::Rc;

fn main() {
    let stock = Rc::new(10);
    let shared = Rc::clone(&stock);
    *stock -= 3;
    println!("{shared}");
}
```

編譯錯誤：

```text
error[E0594]: cannot assign to data in an `Rc`
 --> src/main.rs:6:5
  |
6 |     *stock -= 3;
  |     ^^^^^^^^^^^ cannot assign
  |
  = help: trait `DerefMut` is required to modify through a dereference, but it is not implemented for `Rc<i32>`
```

`Rc` 沒有實作 `DerefMut`，所以不能透過它寫入。真的需要共用又能改，下一集的 `RefCell` 才是答案。

`Rc` 的計數不能應付多個執行緒同時加減，只能在單一執行緒裡用，編譯器會擋；跨執行緒共用要換成 `Arc`（第 14 章第 8 集）。

### 跟 Go 比一比

Go 的指標、slice、map 預設就是共用的，GC 在背後替你算有幾個人在用，誰都能改：

```go
a := &Menu{Name: "夏季菜單"}
b := a // 兩個變數共用同一份，都能改
b.Name = "冬季菜單"
fmt.Println(a.Name) // 冬季菜單
```

Rust 反過來：預設只有一個擁有者，要共用就得明說 `Rc`，計數放在你看得到的地方，而且共用之後預設只能讀。

## 重點整理

- `Rc<T>` 讓同一份資料有多個擁有者：`Rc::new` 建立，`Rc::clone(&a)` 多一個擁有者，`Rc::strong_count(&a)` 讀出擁有者數量。
- `Rc::clone` 只是計數加 1，不複製資料；最後一個擁有者離開，值才被 drop。
- `Rc<T>` 只能讀，不能改（E0594）；要改請看下一集的 `RefCell`。
- `Rc` 只能用在單一執行緒，跨執行緒要用 `Arc`（第 14 章第 8 集）。
- 跟 Go 比：Go 的指標預設共用、誰都能改；Rust 預設單一擁有者，共用要明寫 `Rc`，而且只能讀。
