# `macro_rules!`

## 本集目標

會用 `macro_rules!` 寫簡單的宣告式巨集：寫出比對規則、用 `$名字:片段類型` 抓程式碼、寫好幾條規則，並知道巨集要先定義再使用。

## 正文

### 第一個巨集

`macro_rules!` 後面接巨集的名字，大括號裡是一條或多條規則。每條規則長這樣：`(要比對的樣子) => { 展開成的程式碼 };`。

```rust
macro_rules! double {
    ($x:expr) => {
        $x * 2
    };
}

fn main() {
    println!("{}", double!(3 + 4));
}
```

執行結果：

```text
14
```

- `($x:expr)` 是比對的樣子：`$x` 是我們替抓到的東西取的名字（開頭的 `$` 表示這是巨集的變數），冒號後面的 `expr` 是**片段類型**（fragment specifier），規定它要抓什麼，這裡是「一個運算式」。
- `=>` 後面是展開的結果。展開時，`$x` 會換成抓到的程式碼。
- 規則結尾的分號可以省略，但慣例會寫。
- 呼叫 `double!(3 + 4)` 時，`$x` 是整個 `3 + 4`，所以展開成 `(3 + 4) * 2`，得到 14，而不是手寫 `3 + 4 * 2` 的 11。`expr` 抓的是完整的運算式，不會被旁邊的運算子拆開。

### 片段類型

| 片段類型 | 抓的是 | 例子 |
| --- | --- | --- |
| `expr` | 一個運算式 | `3 + 4`、`price * 2` |
| `ident` | 一個識別字，也就是變數、函式、型別的名字 | `black_tea` |
| `ty` | 一個型別 | `u32`、`Vec<String>` |
| `tt` | 一個 token tree，任何東西都行（第 3 集用到） | `+`、`price`、`(1, 2)` |

還有 `pat`、`stmt`、`block`、`item`、`literal`、`path` 等，這本書不展開。

### 好幾條規則

巨集可以有好幾條規則，編譯器由上往下試，第一條對得上的就用它，像 `match` 的分支：

```rust
macro_rules! order {
    ($drink:expr) => {
        println!("{} x 1", $drink)
    };
    ($drink:expr, $cups:expr) => {
        println!("{} x {}", $drink, $cups)
    };
}

fn main() {
    order!("紅茶");
    order!("咖啡", 3);
}
```

執行結果：

```text
紅茶 x 1
咖啡 x 3
```

`order!("紅茶")` 對上第一條，`order!("咖啡", 3)` 有逗號跟第二個運算式，對上第二條。沒有任何一條對得上時，是沒有錯誤碼的編譯錯誤，例如對只有一條規則的 `double!` 多傳一個引數，訊息是 ``no rules expected `,` ``，沒傳引數則是 `unexpected end of macro invocation`。

### 用 `ident` 產生函式

函式只能收值，巨集還能收「名字」，產生出新的定義。下面一次定義兩個回傳價格的函式：

```rust
macro_rules! drink_fn {
    ($name:ident, $price:expr) => {
        fn $name() -> u32 {
            $price
        }
    };
}

drink_fn!(black_tea, 30);
drink_fn!(coffee, 45);

fn main() {
    println!("{} {}", black_tea(), coffee());
}
```

執行結果：

```text
30 45
```

在函式外面呼叫巨集，展開的是函式定義；用小括號呼叫時，結尾要加分號。這就是巨集最常見的用途：把一大堆長得一樣、只差名字和數字的程式碼，收成一行。

### 巨集裡的變數不會撞名

巨集裡面自己 `let` 出來的變數，跟呼叫端的同名變數是兩回事，編譯器會把它們分開，這叫**衛生**（hygiene）：

```rust
macro_rules! with_tax {
    ($price:expr) => {{
        let tax = 5;
        $price + tax
    }};
}

fn main() {
    let tax = 100;
    println!("{}", with_tax!(tax));
}
```

執行結果：

```text
105
```

呼叫端傳進去的 `tax` 是 100，巨集裡的 `tax` 是 5，各管各的，所以是 105。外層的大括號是巨集規則的邊界，裡面再一層大括號才是展開出來的區塊：巨集用在運算式的位置，展開的結果就必須是運算式，`let` 不是，要包進區塊裡才行。

### 先定義，後使用

函式放在 `main` 的前面或後面都可以，巨集不行。編譯器是由上往下展開，`macro_rules!` 必須寫在使用它的程式碼**之前**。把上面 `double!` 的定義搬到 `main` 後面，編譯會失敗，訊息是 ``cannot find macro `double` in this scope``，而且直接建議「把定義搬到呼叫前面」。

## 重點整理

- `macro_rules! 名字 { (比對的樣子) => { 展開的程式碼 }; }`：由上往下試規則，第一條對得上的就用。對不上是沒有錯誤碼的編譯錯誤。
- `$名字:片段類型` 抓程式碼：`expr`（運算式，抓整個，不會被旁邊的運算子拆開）、`ident`（名字）、`ty`（型別）、`tt`（任何一個 token tree，第 3 集用）。
- 巨集可以在函式外面呼叫，產生函式定義等項目；巨集當運算式用、展開結果要包 `let` 時，用 `{{ ... }}` 多包一層區塊。
- 巨集裡 `let` 出來的變數，跟呼叫端同名的變數互不影響（衛生）。
- `macro_rules!` 必須定義在使用之前，順序跟函式不同。
