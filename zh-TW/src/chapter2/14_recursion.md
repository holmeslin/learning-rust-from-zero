# 遞迴

## 本集目標

寫出會呼叫自己的函式，記得要有終止條件，並知道遞迴太深會把堆疊用完。

## 正文

### 函式呼叫自己

函式裡面可以呼叫它自己，這就是遞迴。算階乘是最典型的例子：`n!` 等於 `n * (n - 1)!`，一路乘到 1 為止：

```rust
fn factorial(n: u64) -> u64 {
    if n <= 1 { 1 } else { n * factorial(n - 1) }
}

fn main() {
    println!("{}", factorial(5));
    println!("{}", factorial(20));
}
```

執行結果：

```text
120
2432902008176640000
```

遞迴一定要有**終止條件**：`n <= 1` 時直接回傳 `1`，不再呼叫自己。其他情況呼叫自己，但傳進去的是更小的 `n - 1`，一步一步靠近終止條件。少了終止條件，函式就會一直呼叫下去。

型別用 `u64`，是因為階乘長得很快：用 `i32` 的話，13 的階乘就已經超出範圍，會是第 1 章第 16 集的溢位 panic。`u64` 可以算到 20 的階乘。

### 費氏數列

函式也可以在一個運算式裡呼叫自己兩次：

```rust
fn fib(n: u64) -> u64 {
    if n < 2 { n } else { fib(n - 1) + fib(n - 2) }
}

fn main() {
    for i in 0..6 {
        println!("fib({i}) = {}", fib(i));
    }
}
```

執行結果：

```text
fib(0) = 0
fib(1) = 1
fib(2) = 1
fib(3) = 2
fib(4) = 3
fib(5) = 5
```

這個寫法會重複計算很多次同樣的值，`n` 一大就變得很慢。這一集只看遞迴的形狀，不處理效率。

### 遞迴太深會用完堆疊

每呼叫一次函式，都會佔用一塊記憶體放這次呼叫的資料，函式還沒結束就不會還回來。這塊記憶體叫堆疊（stack），第 3 章會好好介紹。堆疊的大小是固定的，遞迴太深就會用完：

```rust,no_run
fn sum_to(n: u64) -> u64 {
    if n == 0 { 0 } else { n + sum_to(n - 1) }
}

fn main() {
    println!("{}", sum_to(1000000));
}
```

這支程式能編譯，但用 `cargo run` 執行時，在一般的電腦上遞迴一百萬層就會把堆疊用完，印出 `thread 'main' (……) has overflowed its stack` 和 `fatal runtime error: stack overflow, aborting`，然後被作業系統中止。這不是 panic，結束碼也不是 101，程式沒有機會做任何善後。把 `1000000` 換成 `10000`，就會正常印出 `50005000`。

所以：遞迴的深度要有把握，不確定會有多深的工作，改用迴圈比較安全。

### 跟 Go 比一比

Go 的 goroutine 堆疊會依需要自動長大，上限預設是 1 GB，所以 Go 裡遞迴一百萬層通常沒事。Rust 的堆疊大小固定（主執行緒通常是 8 MB 左右，依作業系統而定），同樣的遞迴深度在 Rust 就會用完。從 Go 轉過來，不要沿用「遞迴很深也無所謂」的習慣。

## 重點整理

- 遞迴就是函式呼叫自己；一定要有終止條件，而且每次呼叫都要更靠近它。
- 階乘長得很快，要選夠大的型別（`u64`），否則會溢位 panic。
- 每層遞迴都佔用堆疊；堆疊大小固定，遞迴太深會 stack overflow，程式被作業系統中止，不是 panic。
- Go 的堆疊會自動長大，Rust 的不會；很深的重複工作改用迴圈。
