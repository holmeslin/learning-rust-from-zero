# `std::fs` 檔案操作

## 本集目標

用 `std::fs` 讀寫檔案、建立與刪除資料夾、列出資料夾內容；分得清楚「一次讀寫整個檔案」與「開啟 `File` 慢慢讀寫」，也知道檔案錯誤怎麼判斷種類。

## 正文

這一集的範例都會在目前的工作目錄（你執行 `cargo run` 的地方）建一個以 `teashop-` 開頭的資料夾，用完再整個刪掉。路徑直接寫字串，為什麼可以，下一集說明。

### 一次讀寫整個檔案

最常見的需求只要兩個函式：`fs::write` 把內容整個寫進檔案（沒有就建立，有就蓋掉），`fs::read_to_string` 整個讀成 `String`。這一集的函式都回傳 `io::Result`，所以 `main` 回傳 `Result`（第 9 章第 11 集），用 `?` 往外丟：

```rust
use std::fs;

fn main() -> Result<(), std::io::Error> {
    fs::create_dir_all("teashop-menu")?;
    fs::write("teashop-menu/menu.txt", "紅茶,30\n咖啡,45\n")?;

    let text = fs::read_to_string("teashop-menu/menu.txt")?;
    println!("{text:?}");
    let meta = fs::metadata("teashop-menu/menu.txt")?;
    println!("{} 個位元組", meta.len());

    fs::remove_dir_all("teashop-menu")?;
    Ok(())
}
```

執行結果：

```text
"紅茶,30\n咖啡,45\n"
20 個位元組
```

- `create_dir_all` 連中間缺的資料夾一起建，已經存在也不算錯。
- `fs::read` 讀成 `Vec<u8>`，給不是文字的檔案用；`fs::metadata` 查大小與種類（20 個位元組：兩行各 10）。
- `remove_dir_all` 連裡面的東西全刪，路徑寫錯很危險。檔案很大、或要逐行處理時，不要整個讀進記憶體，用下面的 `File`。

### `File`：開啟之後慢慢讀寫

`File::create` 開一個要寫的檔案（已存在就清空），`File::open` 開一個要讀的。`File` 同時實作 `Read` 與 `Write`（第 1 集），所以 `writeln!`、`BufReader`（第 2 集）都能直接用。要接在後面寫，用 `OpenOptions`：

```rust
use std::fs::{self, File, OpenOptions};
use std::io::{BufRead, BufReader, Write};

fn main() -> Result<(), std::io::Error> {
    fs::create_dir_all("teashop-orders")?;
    let path = "teashop-orders/orders.txt";

    let mut file = File::create(path)?;
    writeln!(file, "紅茶")?;
    writeln!(file, "咖啡")?;
    drop(file);

    let mut file = OpenOptions::new().append(true).open(path)?;
    writeln!(file, "奶茶")?;
    drop(file);

    let reader = BufReader::new(File::open(path)?);
    for line in reader.lines() {
        println!("{}", line?);
    }

    fs::remove_dir_all("teashop-orders")?;
    Ok(())
}
```

執行結果：

```text
紅茶
咖啡
奶茶
```

第 3 章第 4 集說「檔案要到第 17 章才會學，但它靠的就是 drop」：`File` 離開作用域（或像這裡明確 `drop(file)`）就自動關閉，不用像 Go 寫 `defer f.Close()`。這裡要重新開同一個檔案，所以先 drop 掉上一個。`OpenOptions` 的 `append(true)` 之外還有 `read`、`write`、`create`、`truncate` 可以自己組合。

### 錯誤要看 `kind()`

檔案操作失敗的錯誤型別是 `std::io::Error`。它的 `kind()` 回傳 `ErrorKind`，判斷「是哪一種」用這個，不要比對訊息文字：

```rust
use std::fs;
use std::io::ErrorKind;

fn main() {
    match fs::read_to_string("no-such-file.txt") {
        Ok(text) => println!("{text}"),
        Err(e) if e.kind() == ErrorKind::NotFound => println!("找不到檔案：{:?}", e.kind()),
        Err(e) => println!("其他錯誤：{e}"),
    }
}
```

執行結果：

```text
找不到檔案：NotFound
```

`{e}` 印出來是作業系統給的英文，Linux 與 macOS 是 `No such file or directory (os error 2)`，Windows 的文字不一樣，所以這裡不印它。常見的種類有 `NotFound`、`PermissionDenied`、`AlreadyExists`（重複建立同名資料夾）。

### 列出資料夾：順序不保證

`fs::read_dir` 回傳走訪資料夾的迭代器，每個元素是 `io::Result<DirEntry>`。**順序由作業系統決定**，要固定就自己排序：

```rust
use std::fs;

fn main() -> Result<(), std::io::Error> {
    fs::create_dir_all("teashop-files/archive")?;
    for name in ["menu.txt", "orders.txt", "cups.txt"] {
        fs::write(format!("teashop-files/{name}"), name)?;
    }

    let mut names: Vec<String> = Vec::new();
    for entry in fs::read_dir("teashop-files")? {
        names.push(entry?.file_name().to_string_lossy().into_owned());
    }
    names.sort();
    println!("{names:?}");

    fs::remove_dir_all("teashop-files")?;
    Ok(())
}
```

執行結果：

```text
["archive", "cups.txt", "menu.txt", "orders.txt"]
```

`file_name()` 回傳 `OsString`（作業系統的檔名不一定是合法的 UTF-8），`to_string_lossy()` 轉成 `Cow<str>`（第 13 章第 10 集），不合法的位元組換成 `�`，`into_owned()` 變成 `String`。其他常用函式：`fs::copy`（複製）、`fs::rename`（改名或搬移）、`fs::remove_file`（刪檔案）、`fs::create_dir`、`fs::remove_dir`（單層、要是空的才刪得掉）。

### 跟 Go 比一比

```go
os.WriteFile("menu.txt", []byte("紅茶,30\n"), 0o644) // 要給權限
entries, _ := os.ReadDir("teashop-files")          // 已經依檔名排好
```

- `os.ReadDir` 保證依檔名排序；Rust 的 `read_dir` 沒有，沒排序就印出來，不同機器上的順序可能不同。
- Go 的 `os.WriteFile` 要給權限；Rust 的 `fs::write` 沒有這個參數。
- 判斷找不到檔案，Go 用 `errors.Is(err, fs.ErrNotExist)`，Rust 用 `e.kind() == ErrorKind::NotFound`；Go 靠 `defer f.Close()` 關檔，Rust 靠 drop。

## 重點整理

- `fs::write`、`fs::read_to_string`、`fs::read` 一次讀寫整個檔案；`fs::create_dir_all`、`fs::remove_dir_all`、`fs::metadata` 處理資料夾與資訊；路徑相對於目前的工作目錄。
- `File::create`、`File::open`、`OpenOptions` 開啟檔案；`File` 是 `Read` 也是 `Write`，可以搭配 `BufReader`、`writeln!`；離開作用域就自動關閉。
- 檔案錯誤是 `std::io::Error`，用 `kind()` 比對 `ErrorKind::NotFound` 這類種類；訊息文字依作業系統而不同。
- `fs::read_dir` 的順序不固定，要固定就先收進 `Vec` 再 `sort()`。
- 函式回傳 `io::Result` 時，`main` 回傳 `Result` 加 `?` 最省事。
