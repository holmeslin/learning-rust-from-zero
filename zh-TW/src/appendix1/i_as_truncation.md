# `as` 的截斷規則

## 本集目標

把 `as` 在整數、浮點數、`char`、`bool` 之間轉換的規則整理清楚：哪些會截斷、哪些會取極值，並知道需要檢查範圍時該怎麼做。

## 正文

第 1 章第 17 集說過，`as` 轉成比較小的型別時會被截斷，而且不會報錯。這一集把規則整理完整。有一點先講：`as` 在 debug 與 release 下結果都一樣，永遠不會 panic，這跟第 1 章第 16 集的算術溢位不同。

### 整數轉整數

```rust
fn main() {
    let big: i32 = 300;
    println!("{big:b}");
    println!("{:b}", big as u8);
    println!("{}", big as u8);
    let minus: i32 = -1;
    println!("{}", minus as u8);
    let byte: u8 = 200;
    println!("{}", byte as i8);
}
```

執行結果：

```text
100101100
101100
44
255
-56
```

300 的二進位是 `1_0010_1100`（附錄一 g 的 `{:b}`），`u8` 只放得下右邊 8 個位元 `0010_1100`，也就是 44。規則依來源與目標的大小分三種：

- 目標比較小：只留下低位元，其餘直接丟掉。`-1` 的位元全是 1，留 8 個就是 255。
- 目標一樣大、只是有號變無號（或反過來）：位元不變，重新解讀。`200u8` 的位元解讀成 `i8` 是 -56。
- 目標比較大：數值不變。有號數往上補符號位元，所以 `-1i8 as i32` 還是 -1；無號數補 0，`255u8 as i32` 是 255。有號數轉到更大的無號型別時，先補符號位元再重新解讀：`-1i8 as u32` 是 4294967295。

### 浮點數轉整數

小數捨去，第 1 章第 17 集說過。放不下的時候，不會繞回去，而是取目標型別的最小或最大值；`NaN` 變成 0：

```rust
fn main() {
    let a: f64 = 300.7;
    let b: f64 = -5.0;
    let c: f64 = 1e10;
    let d: f64 = f64::NAN;
    println!("{}", a as u8);
    println!("{}", b as u8);
    println!("{}", c as i32);
    println!("{}", d as i32);
}
```

執行結果：

```text
255
0
2147483647
0
```

`300.7` 超過 `u8` 的 255，變成 255；`-5.0` 低於 0，變成 0；`1e10` 超過 `i32::MAX`，變成 `i32::MAX`。每次都得到一樣的結果。

整數轉浮點數則是取最接近的值，位數太多會失去精度：`16_777_217 as f32` 變成 16777216，`9_007_199_254_740_993_i64 as f64` 變成 9007199254740992。

### `char`、`bool` 與 `u8`

```rust
fn main() {
    let code: u8 = 97;
    let letter = 'z';
    let zh = '中';
    let yes = true;
    println!("{}", code as char);
    println!("{}", letter as u8);
    println!("{}", zh as u32);
    println!("{}", zh as u8);
    println!("{}", yes as i32);
}
```

執行結果：

```text
a
122
20013
45
1
```

- 只有 `u8` 可以 `as char`；`u32 as char` 是 E0604（要用 `char::from_u32`，這本書不展開）。
- `char as u32` 是它的編碼，`'中'` 是 20013；`char as u8` 又是截斷：20013 的低 8 位元是 45。
- `bool as 整數` 是 1 或 0；反過來不行，`n as bool` 是 E0054，要寫 `n != 0`。

### 需要檢查範圍的時候

`as` 不檢查，所以放不下的時候要自己判斷。第 6 章的範圍模式剛好派上用場：

```rust
fn main() {
    let big: i32 = 300;
    let safe = match big {
        0..=255 => big as u8,
        _ => 255,
    };
    println!("{safe}");
}
```

執行結果：

```text
255
```

不會遺失資訊的轉換，改用第 8 章第 13 集的 `From`：`i64::from(x)` 只有在 `x` 一定放得下的時候才存在，`u8::from(300_i32)` 這種可能遺失的轉換是 E0277。標準函式庫還有 `TryFrom`，放不下時回傳 `Result`，這本書不展開。

第 2 章第 12 集的 `usize` 也要小心：`3usize as i32 - 5` 是 -2，但再 `as usize` 回來會是 18446744073709551614，不是 -2。

### 跟 Go 比一比

Go 的變數轉型也是截斷：`uint8(big)` 跟 Rust 的 `big as u8` 結果相同。差別在浮點數：Go 的浮點數轉整數放不下時，規格說結果由實作決定，不同的電腦可能得到不同的數；Rust 一律取最小值或最大值，`NaN` 是 0，到處都一樣。

## 重點整理

- `as` 永遠不會 panic，debug 與 release 結果相同。
- 整數轉整數：目標較小只留低位元；大小相同只換有號或無號是重新解讀；目標較大時有號補符號位元、無號補 0。
- 浮點數轉整數：捨去小數；放不下取最小或最大值；`NaN` 是 0。整數轉浮點數可能失去精度。
- 只有 `u8` 能 `as char`；`char as u8` 會截斷；`bool as 整數` 是 1 或 0，整數轉 `bool` 要寫 `n != 0`。
- 要檢查範圍，用 `match` 加範圍模式；不會遺失資訊的轉換用 `From`。
- Go 的浮點數轉整數放不下時結果由實作決定，Rust 取極值。
